# スライド

## 構造の型
`assets/slides-template.html` をコピーして始める（1枚 = 1920x1080 の `<section data-slide>`、`window.__slides` で送り、印刷CSSでPDF化）。
トンマナは `:root` のトークンだけで決める。

## 作り方
1. まず**1枚1文**の構成表を作る（「このスライドで言いたいこと」を1文で）。文が書けないスライドは不要。
2. 各スライドの「肝」を1つ決める（大きな数字、1枚の画、1つの図）。それ以外は小さく、少なく。
3. 情報の種類ごとにレイアウトの型を3〜5個に絞って使い回す（表紙／見出し＋本文／大きな数字／画像全面／比較）。毎回違うレイアウトにすると散らかる。
4. 図はSVGかHTMLで描く（後から直せる）。

## 撮り方
```bash
node .claude/skills/code-craft/scripts/shoot.mjs deck/index.html --mode slides --pdf --out out/shots/v1
```
- `sheet.png` で全体を一覧し、**縮小しても各スライドの肝が分かるか**を見る。
- 文字のはみ出し、行末の1文字だけの行（泣き別れ）、詰め込みすぎを直す。
- 提出物は `deck.pdf`。

## AIっぽいスライドのサイン
- 全スライドが「見出し＋箇条書き3〜5個」
- アイコン＋短文のカードが3枚並ぶ
- 抽象的な言葉だけで数字・固有名詞・具体例がない

## 動きのあるスライド（WebGL / 1つの世界を進む型）で学んだこと
- **「下からフワッ」とカメラのゆっくり移動だけだと、すぐ飽きられる**。見せ場ごとに違う種類の動きを用意する：1文字ずつマスクからせり上がる／叩きつける（拡大＋ぼけ→定位置）／数字の数え上げ／衝撃（揺れ＋白フラッシュ）／素材に合った転換（例：生コンが流れ込み、固まって割れる）。
- **メリハリは速さの差で作る**：3秒かけて光が回り込む静かな画面のあとに、0.1秒で叩きつける画面を置く。全部同じ速さにしない。
- **デザインの文法を1つ決める**（例：建築図面の枠・目盛り・表題欄・寸法線・等幅の英字ラベル）。「大きい文字＋説明」を並べるだけだと作品にならない。
- **前の画面の値が次へ残るバグ**に注意。書いていない値は既定値で埋めるか、明示的に null を「上書き」として扱う（`b ?? a` だと null が無視される）。
- **画面の拡縮**は `transform-origin: 50% 50%` ＋ `translate(-50%,-50%) scale(k)`。1920×1080 以外の画面で必ず撮って確かめる（ぴったりのサイズでしか撮らないと気づけない）。
- **重いWebGLの確認**：撮影環境はソフトウェア描画で遅い。ページに `?still`（go のたびに1回だけ描く）と `?rec`（仮想の時計で1コマずつ進める。CSSの動きも `document.getAnimations()` で同じ時計に合わせる）を用意し、`scripts/record-frames.mjs` で実際の速さどおりの動画にする。普通の画面録画はカクカクで動きの判断に使えない。
