# サイト（LP・ポートフォリオ・体験型）

## 構造の型
- デザイントークン（色・書体・余白・角丸・影・モーションの速さ）を CSS 変数に集約
- セクション表（ID・見せたいこと・肝・操作・FB）をデータとして持つ
- 1セクションに肝は1つ。ファーストビューは「一番言いたいこと」と「次にすること」だけ

## 撮り方
```bash
node .claude/skills/code-craft/scripts/shoot.mjs http://localhost:5173 --viewports desktop,mobile --full --out out/shots/v1
```
- desktop と mobile を必ず両方撮る。モバイルで崩れていないサイトの方が少ない。
- 横はみ出しは shoot.mjs が数値で検出する。
- インタラクション（ホバー、開閉、遷移アクション）は Playwright で操作した状態も撮る（`page.hover` → screenshot など、プロジェクトに小さなスクリプトを置く）。

## 体験型サイト
- スクロール連動は行き過ぎ・戻りで体験が崩れやすい。シーンごとの**遷移アクション**にして、クリアで次へ進める。
- 案内UIは静かに：小さな半透明ラベルが細い線で操作する場所を指し、残りの回数・距離だけを出す。
- 自動操作のスモークテスト（最初から最後まで操作して完走できるか）を用意し、UIを触るたびに回す。

## UIの案を出すとき
- いきなり3案出すなら、方向性を変える（情報量・トンマナ・配置）。同じトンマナの色違い3案は意味がない。
- 社内レビューで「AIっぽい」と言われたら、まずシーンとUIのトンマナが同じになっていないかを疑う。
- 削りすぎて次の行動が分からなくなったら戻す。字幕型・ラベル型など2案まで絞って比較する。
