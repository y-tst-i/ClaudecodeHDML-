# これができるようになるための道筋

記事の作者がやっていたことを分解すると、必要な力は3つだけです。

1. **AIに「見せて」「直させる」ループを回す力** … カット表 → FB → 修正 を v1〜v9 まで回した
2. **言葉で質感・動き・センスを指示する力** … 「未完成っぽいから削る」「シーンが派手ならUIはミニマル」
3. **最低限のthree.jsの読み書き** … AIが書いたコードの「どこを直せばいいか」が分かる程度

コードを全部自分で書けるようになる必要はありません。**どこに何が書いてあるか分かり、具体的に指示できる**ことが目標です。

---

## ステップ0：まず動かす（30分）

```bash
npm install
npm run dev
```

- `http://localhost:5173/` で映像、`?mode=experience` で体験型サイト
- `npm run render` で MP4 が出ることを確認

ここで「映像とWebが同じコードから出ている」ことを体感するのが一番大事です。

## ステップ1：数字をいじって仕組みを知る（1〜2日）

AIに頼らず、自分で `src/` を直接いじってください。壊しても `git checkout .` で戻せます。

| やること | 触る場所 | 学べること |
|---|---|---|
| BPMを 128 → 174 に | `src/config.js` | ビートに合わせた切り替えの仕組み |
| テーマカラーを変える | `src/config.js` | 色を1か所で管理する意味 |
| 質感を1つ追加（例：`MeshNormalMaterial`） | `src/scenes/s1-materials.js` の `materials` | three.js のマテリアル |
| カメラの画角を変える | `src/scenes/s2-gallery.js` の `shots` | カメラワーク・ease |
| 破片の飛び方を変える | `src/scenes/s3-shatter.js` の「1つの式」 | 全要素を1式で動かす考え方 |

**ポイント：** すべての `update(t)` は「時刻 t だけで絵が決まる」作りです。これが「映像書き出し」と「Web」の両立の鍵です。

## ステップ2：Claude Code にカット表で指示する（2〜3日）

1. `npm run cuts` → `docs/CUTSHEET.md` を開く
2. 気になるカットの `fb` を `src/cuts.js` に書く
   ```js
   { id: 'C04', ..., fb: 'カメラが近すぎて像の全体が見えない。像は画面中央、台座まで入れて' },
   ```
3. Claude Code にこう頼む：
   ```
   src/cuts.js の fb を全部反映して。直したら probe で該当カットを確認し、
   npm run cuts でカット表を更新して。fb 欄は「対応済み：〜」に書き換えて。
   ```
4. 新しいカット表を見て、また FB を書く。これを v5 くらいまで回す

**良いFBの書き方（記事から）**

| ダメ | 良い |
|---|---|
| なんかチープ | 質感とモーションがチープ。本気でやって（←初回はこれでも効く） |
| かっこよくして | Normal/Depth は未完成っぽく見えるので削除。クロームを目立たせて |
| 色を揃えて | C19〜21も背景をテーマカラーに。一連のポスター世界のはず |
| ガラスが変 | 割れるガラスがチープ。C03 のガラスの質感に揃えて |
| 破片が変 | 破片が2層に見える。全部を1つの式で動かして |

→ **「何が」「なぜダメで」「何を基準に」** の3点が入っていると一発で直ります。

## ステップ3：自分の作品を作る（1週間）

記事と同じ順番でやります。**白紙のカット表から始めない**のがコツ。

### 3-1. アイデアを雑に書く
```
全体：〇〇な印象にしたい。Boldなタイポを効果的に。
シーン1：〜
シーン2：〜
（素材リスト：ロゴSVG、キャラの3Dモデル(.glb)、メンバー写真…）

表現は過剰でもOK。アイデアはヒントで、再現を目指す必要はありません。
これをもとにコマ割りと音楽ブリーフを提案して、src/cuts.js と src/scenes を作り直して。
```

### 3-2. 技術検証を先にやらせる
いきなり本番を作らず「このシーンは技術的にできる？試作して」と頼む。
記事では深度推定（MoGe-2 / Depth Anything 3 / BiRefNet）の結果を見て、パーティクル案を捨てて「素材の図鑑」に方針転換しています。**検証結果を見て企画を変えていい**。

### 3-3. v1 → FB ループ
ステップ2と同じ。最初の一言は「本気でやってください！」でOK。

### 3-4. CGっぽさを消す
- 実写テクスチャ（ガラスのヒビ、網点、レンズの汚れ）をAIにリストアップさせ、自分で集めて `public/textures/` へ
- 看板や小物は画像生成。プロンプトもAIに書かせる
  ```
  ネオン街の看板が12枚必要。サイズ・内容・画像生成用プロンプトを表にして。
  アクリルのくすみ、ネオン管のガラス、錆びた金具まで指定して。
  ```

### 3-5. 体験型サイトのUIは「センス」を渡す
AIにUIを作らせるとシーンと同じ派手さで作ってしまう（＝AIっぽい）。最初からこう渡す：
```
シーンが派手な分、UIはミニマルに洗練させる。その緩急がセンス。
ただしミニマルでも細部は徹底的に作り込む。
8の倍数、ボタン高さ32px、角丸なし、ホバーは色変化のみ、英字の字間0。
```
このルールは `CLAUDE.md` に書いてあるので、このリポジトリでは毎回自動で守られます。

## つまずきやすい所

- **Webと映像で絵がズレる** → `Math.random()` や `Date.now()` を使っていないか。乱数は `mulberry32(CONFIG.seed)`
- **AIが「直しました」と言うけど直ってない** → 「probe で該当秒数の画像を出して自分で確認してから報告して」と毎回言う（CLAUDE.md にも書いてある）
- **全部が平均的な絵になる** → プロンプト一発で終わらせない。具体的なFBを何回も回すことでしか個性は出ない

## 次に覚えると良いもの

- Figma MCP：カット表をFigmaで管理したい場合（記事と同じ運用）
- GLTFLoader：自分のキャラの3Dモデル（.glb）を読み込む
- ポストエフェクト（バレル歪み・色収差・グリッチ）：`three/addons/postprocessing/`
- 音：音楽を先に決め、BPMを `config.js` に入れて全部をビートに合わせる
