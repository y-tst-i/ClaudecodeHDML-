# 絵のなかをキャラが歩くまで（背景の絵 + VRM + ARDY）

解説動画（約4分）の方法を、手順・計算式・検証済みコードの形にしたもの。3D背景は作らない。
絵に合わせて「見えない床と箱」だけを置き、その上にVRMキャラを立たせて歩かせ、アニメ塗りで絵になじませる。

## このスキルでできること／できないこと
- できる: 絵からカメラを推定する計算、1mマス目での確認、ARDYへの頼み方、足の補正（つま先歩き・階段合わせ）のコード、各手順のチェック項目。
- できない（利用者の制作環境が必要）: ARDYの動き生成（GPU、Meta-Llama-3-8B-Instructの利用申請が必要）、VRMの描画・影・隠れの処理。
- 動画に映らない内容は推測で埋めていない。分からなかった点は末尾の「未確認」を見る。数値の根拠は `references/video-notes.md`。
- `scripts/`（camera.py・grid_overlay.py・fit_stairs.py・foot_correct.py・selftest.sh）と `references/` は、別配布の `picture-walk-vrm-ardy-toolkit.zip` に入っている。このスキルのフォルダに展開して使う。無い場合は、下の式と手順からその場で書き起こして使う（検証は `selftest` と同じ観点で行う）。

## 全体の流れ
1. 絵ごとに「どこから見た絵か」（カメラ）を推定する
2. 見えない床・段・ベンチの箱を絵に合わせて置く
3. ARDYに文章と通り道（場所と向き）を渡して動きを作る
4. 動きをVRMに移し、足の補正（つま先・階段）をする
5. アニメ塗りで描く（床の明るさで日向/日陰、影は見えない床に落とす）

**最優先は 1。** カメラがずれると足の位置・影・大きさが全部ずれる。

## 1. カメラ推定（絵ごとに）

座標系: x=右、y=上、z=奥（道が伸びる向き）。カメラは (0, H, 0)、yaw=右向き、pitch=上向き（下向きはマイナス）。
画像の中心 (cx, cy) は **元の絵** の中心。表示用に切り出した画像の中心ではない。

### 1-A. 消失点が1つの絵（歩道）
1. 奥へのびる線（道の縁・塀の下端など）を複数たどり、集まる点 (u, v) を求める
2. レンズは絵から読めないので **35mm と決める**（横の画角 54.4°。計算: `2·atan(18/35)`）
3. `F = (W/2) / tan(hfov/2)`（Wは元の絵の幅px）
4. 傾きと向き:
   ```
   pitch = atan((v - cy) / F)                  # 消失点が中心より下 → 上向き
   yaw   = atan(-(u - cx) * cos(pitch) / F)    # 消失点が中心より左 → 右向き
   ```
5. 目の高さ（水平線）= 消失点の行 v。カメラの高さ H は大きさの基準から決める（1-C）

### 1-B. 消失点が2つの絵（バス停）— レンズまで絵から決まる
直角に交わる2方向（道路の線と待合所の横の線）の消失点 P1, P2 から:
```
F² = -((u1-cx)(u2-cx) + (v1-cy)(v2-cy))     # F² ≤ 0 なら線のなぞり直し
hfov = 2·atan((W/2)/F)
P1 を世界の z 軸として 1-A の式で pitch / yaw
```
2点を結ぶ線の傾きが水平でなければ、その分（roll）を先に戻してから計算する。
動画の値: 42.3° / 下向き 5.62° / 右向き 34.17°。

### 1-C. 大きさの基準（絵には目安が無い）
実物の高さが分かるものを1つ決める（歩道: 塀 1.3m → カメラ 0.70m、バス停: ベンチ 0.35m → カメラ 1.46m）。
地面に立つ物の下端・上端の行から、カメラの高さ H を二分法で解く（`scripts/camera.py` の `camera_height_from_reference`）。
この「決めた大きさ」で全てのメートル値が決まる。決めた値を必ず記録する。

### 1-D. 1mマス目で確認（必須）
`scripts/grid_overlay.py` で床に1m格子と身長1.28mの目印を重ねる。
- 格子が消失点へ向かって細くなる／目印が遠いほど **距離に反比例して** 小さくなる
- 動画の例: 4.1m→907px、5.0m→735px、7.0m→530px、7.4m→502px（907/502 ≈ 7.4/4.1）
- 合わなければ 1 に戻る。ここで合わせずに先へ進まない

### 1-E. 光と影
- キャラの体の1点から **太陽の反対方向へ** たどり、床に当たった所の「絵の明るさ」(0〜1) を読む
- 動画の例: 0.02, 0.03 → 日陰、0.29 → 日向。メーターは0〜約0.6で、〜0.10 日陰／0.10〜0.22 半影／0.22〜 日向 と読めた（図から推定。絵ごとに調整）
- 日陰ならキャラを絵の影の色へ暗くする。影は同じ床に落とし、**見えない床が絵を影の形に暗くする**

## 2. ARDYに動きを作ってもらう

公式: https://github.com/nv-tlabs/ardy （コード Apache-2.0、重みは別ライセンス）。
導入: Python 3.11、PyTorch ≥2.4（CUDA）、`pip install -e ".[all]"`、`hf auth login`（Llama-3-8B-Instruct 申請済みであること）。目安: RTX 4090、文章エンコーダで約14GB VRAM。

```
python scripts/generate.py "A person walks forward, stops and turns around, and stands still." \
       --model core --duration 10 --seed 0 --num_samples 2 --output walk
python scripts/visualize.py outputs/walk.npz        # ブラウザで確認
```
出力 `.npz`: `posed_joints`（世界座標 [T,J,3]）、回転、ルート位置、足の接地、`fps`（Core骨格は20）、`text`。

頼み方のコツ（動画より）:
- 文章は **1動作ごとに分ける**。「歩く」と「座る」を1文にすると中腰で歩く
  例: `A person walks forward, stops and turns around, and stands still.`（10秒）→ `A person sits down on a bench.`（4秒）→ `A person sits on a bench, resting.`（2秒）
- 文章だけでは「どこへ歩くか」が決まらない → **通ってほしい点（場所と向き）をいっしょに渡す**（動画の例: 15点、合計16秒）。制約の渡し方は公式READMEの `--constraints` を参照
- 続きを作るとき、直前の **8コマだけ** を見せる（履歴フレームを増やすと前の動きを続けてしまう。公式の `--history_frames` が相当するはずだが、動画に名前は出ない）
- 同じお願いで **2本ずつ作って見比べて選ぶ**
- キャラは脚が短い（動画の例: ARDYの人の0.54倍）。進む距離も同じだけ縮める

## 3. VRMへ移す・置く
- 歩きはじめの **場所と向き** を置けば、歩いた先が目的地（ベンチ）になる。動画のバス停: スタート (6.23, −2.99)、カメラに背中を向けて出発（座標系の原点・軸は動画から不明。自分の絵では床格子の原点を決めて記録する）
- 床は見えない板、段は1段ずつ見えない箱、ベンチなどは見えない箱にする。箱は影を受け、後ろの足を隠す役
- 動きを移したら次の補正へ

## 4. 足の補正（`scripts/foot_correct.py`）

**共通の考え方**（つま先直しも階段合わせもこれ）:
1. 足が止まっている間の足首（と爪先）の移動量を決める
2. **腰は左右の足の移動量の平均だけ動かす**
3. **ひざは二関節IKで曲げ直す**（太もも・すねの長さは変えない）

```python
# 二関節IK: hip, ankle から knee を求める（pole = ひざを曲げる向き。元の動きのひざの向きを使う）
d = ankle - hip; D = norm(d); dn = d / D
a = (l1*l1 - l2*l2 + D*D) / (2*D); h = sqrt(max(l1*l1 - a*a, 0))
pole_perp = normalize(pole - dot(pole, dn) * dn)
knee = hip + a*dn + h*pole_perp
pelvis_delta = (ankle_delta_left + ankle_delta_right) / 2     # 腰
```

### 4-A. つま先歩きの直し
ARDYの歩きは、足が着いている間に **つま先が下を向きかかとが浮く**（動画: 17〜31°、かかと6〜10cm。ふつうは0〜約6°）。原因は書き出しではなくARDYの動きそのもの。
1. **はかる**: 足が着いている間の足の傾き（足首→つま先ベクトルの下向き角）とかかとの高さを、全歩数で出す
2. **直す**（傾いている分、浮いている分だけ元に戻す）:
   ① 足を足首を中心に平らへ戻す（動画の最大 28.4°）
   ② 足首を下げる（同 4.1cm）— 足だけ戻すと脚がのびてしまう
   ③ 腰も下げてひざを曲げ直す（同 2.3cm）
3. **やめる**: 座りはじめ（動画では11秒）から1秒かけてこの直しをやめる。座る動きは元のまま
4. **くらべる**: 同じ歩き・同じ所を「直す前／直した後」で並べる（動画: 17〜31° → 0.7〜5.3°）

```
python scripts/foot_correct.py inspect walk.npz                     # キー・fps・接地の有無を確認
python scripts/foot_correct.py flatten walk.npz walk_fixed.npz --joints map.json --fade-from 11 --fade-dur 1
```
`map.json` は骨格の関節番号（ARDYのモデルごとに違うので自分で確認して書く）:
`{"left":{"hip":..,"knee":..,"ankle":..,"toe":..}, "right":{...}}`
足が着いている判定は「つま先の高さが床近く＆ほぼ静止」（ARDYの接地出力を使うなら `flatten_feet(contacts=...)`）。
基準の足の傾き・つま先の床高さは、直立している最初のフレーム（`--ref-frame`）から取る。

### 4-B. 階段（`stairs`）
1. 階段は正面向きで **奥へのびる線が見つからない**。代わりに **13段のふちをなぞり**、いちばん合う階段を探す（動画: ずれ 5.5px。結果 高さ0.136m・奥行0.197m・カメラ1.02m・下向き1.13°）
   `python scripts/fit_stairs.py --rows <各段の行px> --size W H --fix camera-height=1.02 --fix riser=0.136`
   **値を1つだけ固定すると答えが定まらない**（検証済み）。実寸の仮定を **2つ** 固定する（例: 段の高さ＋カメラ高）
2. ARDYが思っている段（動画: 高さ0.095m）は絵の段（0.136m）より小さい → **高さ 1.43倍、奥行き 1.62倍** に伸ばす（`scale_root_trajectory`。動画の比 0.136/0.095 と一致）
3. 足が止まるたびに、どの段に乗るかを決める（10 → 9 → 8 … → 0）。足が止まる所を **1歩ずつ絵の段の上へ** 動かす。横方向（左右）は変えない
4. 腰は両足の移動の平均、ひざは曲げ直す。続けて 4-A の足の平ら直しを段の高さに合わせて行う
5. 段は1つずつ見えない箱（13段＋奥の踊り場）にして、影を段の形に落とし、うしろの足を段に隠す

```
python scripts/foot_correct.py stairs walk.npz stairs_fixed.npz --joints map.json --axis 0 1 \
   --riser 0.136 --tread 0.197 --start-index 10 --direction -1 --ardy-riser 0.095 --ardy-tread 0.1216
```
`--axis` は歩く向き（x z、水平面）。最初の足はARDYの位置のまま基準にする（絵の段の位置に固定したいなら `stair_deltas(anchor="picture", s_ref=, y_ref=)`）。
出力の `max_leg_stretch_m` が0より大きいと、足が脚の長さより遠い（腰が高すぎる／段が高すぎる）ので動きを見直す。

## 5. 描く（アニメ塗り）
- 床の明るさ（1-E）で日向/日陰を決め、キャラの色を絵に合わせる
- 影は見えない床・箱に落とし、絵が影の形に暗くなるようにする
- 足が平らに着いているか、直す前後を並べて確認する

- [ ] 座りはじめで足の直しを1秒かけてやめた

## 計算の確認方法
`sh scripts/selftest.sh`（numpy・scipy・Pillowが必要）。カメラの往復計算、階段フィットの条件、足の補正（接地足の傾き・脚の長さ・腰=平均・足が滑らない・階段へ正確に着地）を合成データで確認する。
なお、これらは合成データでの検証。実際のARDYの `.npz`（関節の並び・接地の形式）での動作は、利用者の環境で `inspect` から確認すること。

## 未確認（動画から分からなかった点）
- 動画の歩道の「向き 7.20°」は、動画の表示画像から消失点を測っても再現できなかった（傾き3.32°は再現）。元画像の中心の取り方が違う可能性がある。バス停の向き34.17°も測り誤差の範囲を超えて37.7°になった。**自分の絵では必ず 1-D の格子で目視確認する**
- 階段で固定した2つの値、スタート座標 (6.23, −2.99) の座標系、日向/日陰の正確なしきい値と影の濃さの式
- VRMへの移し替え・描画・アニメ塗りの実装そのもの
