# FunTech 級を目指す制作計画

## 差（数字で）
FunTech（experience2026.funtech.inc）の配信ファイルを数えたもの（2026-10-09）と、いまの YOHI。

| | FunTech | YOHI（いま） |
|---|---|---|
| 場面 | 9（boot / volt / museum / neon / poster / breakout / run / shatter / logo） | 5（1本道） |
| 画像・テクスチャ | 約93枚（約22MB） | 8枚 |
| 3Dモデル | 約36（glb・Draco圧縮・KTX2テクスチャ・HDR環境光） | 0（全部2Dのシェーダー） |
| 音 | 約70（場面ごとのBGMループ9本＋効果音、174BPM、16分音符に揃えて鳴らす） | 効果音20＋ビート1本 |
| 仕上げ | 共通のポスト処理（ブルーム・ディザ・走査線・トゥーン・グリッチ等） | カットごとにばらばら |

## 分担
- 監督（ユーザー）：方向・選択・試写室での反応
- Claude：設計、three.js/シェーダーの中心、組み上げ、撮って確認、Codex の成果のチェック
- Codex（`scripts/codex.sh`／codex-images）：素材の量産、切り分けられるコード部品、2人目の批評

## 段階（各段階の終わりに試写室で FB）
1. **土台**：2D → 本物の 3D（three.js のシーン＋共通のポスト処理）。1場面だけ作り込んで「質の基準」を決める
2. **世界観の設計書＋素材の量産**：色・質感・文字・形のルールを1枚に。その範囲で Codex に 30〜50 点
3. **場面を増やす**：5 → 8 前後。場面ごとに違う触り方。独立した部品は Codex、組み上げは Claude
4. **音楽**：場面ごとの BGM ループ＋16分音符に揃えた効果音
5. **仕上げ**：実機の重さ、スマホ、読み込み画面

## 正直な制約
- 3Dモデル（glb）は画像生成では作れない。コードで形を組む（手続き的モデリング）か、2D素材を3D空間に置く「紙芝居的3D」で補う
- このクラウド環境には GPU がない。滑らかさの最終確認は監督の実機で
- Claude の週の使用量に上限がある。量産は Codex に寄せる
